Tools

Real tools, not just toy examples.

Most local AI apps stop at a web search demo. Resident gives a model on your phone tools that do work: a code sandbox, the web, your calendar, and through the Model Context Protocol (MCP) the services you already use. Find your open issues, close one, comment on a pull request.

A code sandbox on the device

A JavaScript interpreter runs on the phone, with no network and no access to your files. The model writes code for arithmetic, dates and data, so the answer is computed, not guessed.

Any MCP server

GitHub, Linear, Notion, Atlassian, Sentry and Hugging Face are a tap away. Anything else that speaks MCP is added by pasting its address.

Big services are no problem

Linear's server offers about 70 tools. Described all at once, they would fill a small model's context before it read your question. Resident opens only the few a request needs, so a 1.7B model uses a server that size correctly.

Sign-in done properly

You sign in on the service's own page, as you would for any app. Resident never sees a password, keeps its access in the iPhone's Keychain and renews it without asking again.

The web, read properly

Search and page reading run on the phone, with no account or key. Long pages are ranked against the question, so the model reads the passages that matter.

Your calendar and reminders

Read and written on the device, with dates understood the way people say them: "tomorrow at five", "next Friday".

What is different

The harness matters more than the model.

A model small enough for a phone reasons well and is easily overwhelmed. What decides whether it gets real work done is what it is shown and what it is allowed to write. Resident controls both, hard, and that is where the reliability comes from.

Context management: what the model is shown

Tools appear when they are needed

A connected service is one line in the prompt until a request needs it. Then the model gets the handful of tools that fit, not all seventy.

Tool definitions are trimmed

Services describe their tools for large models. Resident cuts each description and schema to what is needed to make the call, which halves what the opened tools cost.

Answers from tools are made to fit

Twenty issues with pages of description would fill the context. Resident shortens the long parts first, keeps every item, and says plainly when something was left out. Long web pages are ranked against the question and only the best passages kept.

Nothing is read twice

Each step feeds the model only what is new, old tool results shrink as a chat grows, and long chats are summarised behind the scenes. The tenth question is as quick as the first.

Decoding: what the model is allowed to write

A broken tool call cannot be written

Once the model starts a call, a grammar admits only a tool that exists and arguments that fit its schema. Text and thinking stay free; the call itself cannot come out malformed.

Thinking has a budget

Thinking is switched per chat and capped, so a model does not spend its whole reply reasoning. One that thinks itself out of room is asked again with thinking off.

Mistakes come back with the fix

A call that fails returns what the tool expects. A tool called by the wrong name brings the closest real ones. A repeated call is refused. The model corrects itself instead of looping.

The chores are separate requests

Remembering a fact, naming the chat and tidying a long conversation are each a short request of their own after the reply, so they happen every time and never crowd the answer.

How we check all this: a public suite of 388 scored test requests that any model can be run through.

What it does

An agent, not a chat box.

Remembers you

Keeps a short list of lasting facts you mention. Read it, edit it or switch it off.

Learns your way

Turn something it just did into a skill with one tap. You see and approve every skill before it is kept.

Reads what you give it

Photos, PDFs and documents, and dictation by a speech model that also runs on the device.

Agents

Opinionated, and yours to change.

An agent is a set of instructions, the tools it may use and how hard it thinks. Start with the Assistant, switch to the Coder, or make your own for the things you do often.

The defaults are meant to be right. The numbers are there when you want them: temperature and reply length per agent, sampling per model, thinking per chat.

Automation

Runs from Shortcuts, in the background.
